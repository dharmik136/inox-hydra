# Risk - LinkedIn terms and detection

LinkedIn's User Agreement prohibits automated access and scraping. The product reads pages the creator opens rather than crawling, and gates every request to LinkedIn. It never comments, reacts, connects or messages. It does three things that are not reading, each only when the creator asks: it schedules a post through LinkedIn's private API (**Send to LinkedIn**, the paragraph below), it clicks and scrolls through the creator's own activity during a history import, and it clicks Start a post and types a draft into LinkedIn's composer without posting it.

**Tolerated in practice, not permitted in text (corrected cycle 4).** By LinkedIn's own words there is no carve-out for a passive, own-data, read-only extension: User Agreement 8.2 item 2 names "browser plugins and add-ons" used "to scrape or copy the Services, including profiles and other data", and the Help Center's triad is software that "scrape[s], modif[ies] the appearance of, or automate[s] activity". The default mode touches items 2 and 15 lightly (reading your own pages; a notice and a banner in the page) and is tolerated in practice, not permitted in text; the lawyer's read in mitigation 5 should start from that distinction rather than from "a defensible personal tool", which this note used to say. The enforcement record draws the line the text does not: every documented action is about third-party data at scale, fake accounts, cookie reuse on vendor servers or UI overlay at scale, and none has reached a tool that reads only the member's own pages in the foreground. The creator-facing page in the help, `docs/help/where-each-feature-stands-with-linkedins-terms.md`, quotes the text verbatim and dated beside each feature's standing. A commercial product is judged more strictly.

**The enforcement record, dated (added cycle 4).** Shield wound down in May 2026: its team wrote "Both Google and LinkedIn have made it clear that we cannot continue operating Shield as it was built", the extension was pulled from the Chrome Web Store, and its method was the member's login cookie reused on Shield's servers for background sync [reported, competitors quoting the notice]. Kleo's Chrome extension shut down on 2025-06-20, in its co-founder's words "After 2 years and 70,000+ users, the Kleo Chrome extension has to shut down. LinkedIn told us to."; it overlaid LinkedIn's pages and read them, and Kleo relaunched as a paid web app [founder's own post]. Taplio's founder reported his account permanently suspended in November 2024 "because of my Taplio involvement" [reported]. AuthoredUp, the closest analogue to this product's default mode (reads only pages the user opens, no background activity, no `cookies` permission, archive upload for history), has no reported incident. The ladder this gives: the default install reads foreground own pages with light in-page elements; the import and the composer click are actions on a press; network reading is a disclosed opt-in; Send to LinkedIn is the one feature squarely on 8.2 item 13, off by default and first profile only.

**Most exposed:** [[Voyager Interceptor]] (wraps fetch inside LinkedIn's page), the scrolled [[History Import]], `linkedin_client.schedule_norm_share` ("Send to LinkedIn"), and the Agency tier's sessions: 8.2 item 1 bars using "another's account (such as sharing log-in credentials or copying cookies)", five profiles on one machine is five accounts, and the tool cannot tell whose browser a session came from.

**Send to LinkedIn, named explicitly (added cycle 3).** `schedule_norm_share` (`linkedin_client.py:954-1030`) POSTs `{"lifecycleState": "SCHEDULED", "commentary": ..., "scheduledAt": ...}` to `https://www.linkedin.com/voyager/api/contentcreation/normShares`, an undocumented private endpoint, authenticated with the member's own `li_at` cookie and `JSESSIONID` as a CSRF token. That is a write, not a read: automated content creation on a personal profile through a private API, outside LinkedIn's published terms, and it could affect the account's standing if LinkedIn's systems treat it as automation. It is off by default (`INOX_ALLOW_LINKEDIN_EGRESS`, `egress.py:84`) and the owner has tested it personally, but it ships, so this register names it rather than relying on the Voyager interceptor and the history import to stand in for every exposure.

**Mitigations, in order:**
1. Done: Setup leads with [[LinkedIn Data Archive Import]], LinkedIn's own sanctioned export.
2. Done: "undetectable", "anti-detection" and "stealth" language is gone from the README, the extension doc and the interceptor ([[Gap - Claims the code contradicts]]).
3. Done: the interceptor is an explicit, off-by-default setting with its own disclosure. Retire it if the archive and page readers cover the need.
4. Done (cycle 3): Send to LinkedIn requires a one-time, logged acknowledgement of the paragraph above before an installation's first send, separate from the per-send confirmation that names the account and the time. `docs/ARCHITECTURE.md` §4 and `docs/EXTENSION_AND_SYNC.md` §2 no longer claim zero automated activity or an unconditional "never click".
5. Get a lawyer's read on the extension before the public store listing. Brief it with the clause table in the help page above and with this note's wording: tolerated in practice, not permitted in text.
6. Done (cycle 4, D9): session sync and Send to LinkedIn work in the first creator profile only; the help says each profile's session must come from that creator's own browser on that creator's own machine.
7. Done (cycle 4, item 28): LinkedIn's own analytics export (.xlsx) is imported as the sanctioned source of exact figures, so the interceptor's retirement condition can be stated honestly as "once the analytics export import or an official analytics API covers exact figures" rather than "once the archive covers it" (the archive carries no figures).
8. Done (cycle 4, item 30): the creator-facing terms page in the help, and the store listing's Limited Use disclosures drafted in `release/STORE_DISCLOSURES.md`.
9. Open: the official posting route (Sign In with LinkedIn plus Share on LinkedIn) is parked on the public-client question, answered in `docs/OFFICIAL_POSTING_ROUTE.md`; the Community Management application is an owner action.
10. Keep a dated watch on three external texts that can move under the product: the two Help Center articles (one was updated within a month of 2026-10-26), the Member Post Analytics eligibility page, and the Chrome Web Store policies.
